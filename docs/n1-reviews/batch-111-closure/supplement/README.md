# Supplement to the batch-111 review packet (read-only evidence)

These files are extra evidence for the same snapshot, commit 3b30803e33438dab7a1071aea34ceb7764189c1f (its parent is main f40a139165410be20be06dd0a67928168dae5f63). Both reviewers receive this identical supplement. The files contain no author or reviewer commentary and are not verdicts. `supplement-manifest.json` lists the SHA-256 and size of every file.

- `joyo\pN.txt` (14 files): text extracted with pdfplumber from page N of the official Joyo kanji table (Ministry of Education, Culture, Sports, Science and Technology, 2010-11-30). N is the page that a card's "Usage evidence" line links to: 義 34, 鏡 39, 句 41, 授 72, 修 73, 旬 76, 製 91, 節 93, 率 101, 独 120, 標 and 評 132, 敷 134, 房 142, 養 153. The first line of each file gives the source URL with `#page=N`, and the second gives the PDF sha256. The table's own legend (page 1, item 6) says that entries in round brackets are the 康熙字典体 (Kangxi dictionary) forms. The extraction is a convenience, not a primary source: verify against the PDF when it matters.
- `reading-options.txt`: the complete output of a script written for this project (not the app) that ports the app's reading-quiz option builder. For each of the 15 cards and each quiz reading it lists the curated and fallback wrong options the quiz can draw, checks whether a reading that KANJIDIC2 (on, kun, name readings) or JMdict's single-kanji entries attest for the kanji, but that the card does not list, could be offered as a wrong option, and runs a 400-seed simulation.
- `reading-exposure.txt`: the complete output of a second script that extends the first. It enumerates the wrong options that can actually be drawn in the pools the app builds from the shipped content (the N1 stack, the All stack, and a Starter "Practice more" session that borrows the card), with a 200-seed sampling check.

Limits: both scripts are ports written by the author and were run against the app's source at Android commit 10d98d0db61dcde621463460e6a1e59941b4042b, with Python's random generator. They are not output of the running app, and no device or emulator was used. Their "unlisted reading" and "latent collision" lines are leads for you to judge, not established defects. The complete meaning-quiz simulation (the section "quiz safety simulation") is in the packet's `mechanical-checks.md`; it is shorter than that file's 4,000-character cap per section, so it is complete there.
