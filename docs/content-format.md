# Content format (schema version 1, draft)

The Android app [Ensō Nihongo](https://github.com/stop-cran/kanji-cards-android) reads this repository. Anyone can fork it and
point the app at their fork. `tools/validate.py` checks structural constraints; dictionary accuracy, origins, natural examples,
and useful navigation still require editorial review.

```
manifest.json          generated by tools/build_manifest.py: schemaVersion, contentVersion, SHA-256 per file
kanji/<char>.md        one card per kanji, e.g. kanji/日.md
words/<word>.md        one article per word, e.g. words/大小.md
articles/<slug>.md     free-form articles (no front matter required)
strokes/<char>.json    generated by tools/generate_strokes.py from KanjiVG
scenes/<word>.json     optional named scene catalog (separate manifest scenes map)
images/<name>.webp     scene assets (separate raw-byte-hashed manifest images map)
listening/<id>.json    N5 listening packages (separate manifest listening map)
audio/<id>.ogg         approved mono Opus recordings (separate raw-byte-hashed audio map)
```

## N5 listening

The [listening authoring and schema guide](listening-n5.md) specifies original short dialogues/monologues, exactly three
questions per passage, four stock voices, mild N5 pacing, optional context images and hash-bound final-recording approval.
Listening difficulty includes essential spoken vocabulary and speech demands, not written kanji lists or grammar alone.
Draft JSON without audio is valid but unavailable for scoring. Never treat automated validation as actual listening approval.
Run `tools/check_content_budget.py` as well as validation and manifest regeneration before publishing media.

## Kanji card

Restricted YAML front matter followed by the Markdown article. The app accepts only `key: value` scalars and inline `[a, b]` lists.
Do not use block lists, nested mappings, multiline scalars, inline comments, YAML escapes, or commas inside quoted list items.
For example, `onyomi: [アン]` is supported; a YAML block sequence is not. The parser only removes surrounding quotes; it does not decode escapes.
Use UTF-8 with LF or CRLF line endings. Optional article front matter follows the same flat subset; ordinary Markdown articles do not
need metadata. The validator preserves the app's plain-Markdown fallback rather than treating every opening thematic break as a header.
Mapping-shaped opening blocks are checked as metadata; use `***` for an opening thematic break to avoid that ambiguity.

| Field | Meaning |
| --- | --- |
| `kanji` | The character; must equal the file name. This is the card's stable ID. |
| `title` | Short English meaning used as an answer choice in the meaning quiz; unique across cards. |
| `jlpt` | 1–5 (N5 is easiest). Community study classification, not an official exam syllabus. Follow the [source policy and documented exceptions](jlpt-levels.md); do not infer a level from a missing value. |
| `tags` | Free tags, e.g. `jlpt-n5` (must match `jlpt`), `starter` (the original words-driven starter set), `grade-1`, `pictograph`, `indicative`, `compound`, `phonetic-compound`. Use `structure-unclassified` when a historical structural classification has not been established. Stacks will filter on tags. |
| `strokes` | Stroke count; must match `strokes/<char>.json`. |
| `radical`, `radicalNumber` | The key (radical) and its classical number (1–214). |
| `phonetic` | Optional; a verified phonetic component. Omission means it is not supplied, not necessarily that the character has none. |
| `onyomi`, `kunyomi` | Lists in kana; kunyomi uses `.` before okurigana and `-` for affixes. |
| `distractors` | The app can omit this field, but authored cards must supply at least two distinct, plausible wrong options with existing cards; never include the card itself. |

### Quiz authoring

The meaning quiz displays a kanji and offers other cards' English titles as answers. For new cards, curate **three** semantically
distinct wrong options for the default four-choice quiz. Two remain structurally valid for older cards, but the app fills missing
choices from other cards, preferring shared tags. It only deduplicates exact title strings: different English synonyms can still
produce two defensible answers. Keep useful semantic comparisons in the body even when they are unsuitable as wrong answers.

Editorial review must check the displayed titles against the target's ordinary meanings, not merely look for duplicate strings.
This behavior was checked in [QuizBuilder](https://github.com/stop-cran/kanji-cards-android/blob/8c130a25bdb4e444a80a2f78ef0d11b04bddc12f/app/src/main/java/io/github/stopcran/kanji/core/quiz/QuizBuilder.kt);
larger quizzes or a changed app can still require fallback choices. The validator checks structure, not semantic ambiguity.

## Word article

Word-header keys must be unquoted, unindented identifiers matching `[A-Za-z_][A-Za-z0-9_-]*`;
whitespace before the colon is allowed. Quoted, escaped, tagged and anchored keys are unsupported, even if a later plain
declaration repeats the same field. This is checked before YAML can decode or collapse duplicate names.
The closing `---` delimiter may have trailing whitespace or a whitespace-separated `#` comment; this exception does not allow
inline comments on fields. A prefix such as `---notes` is not a closing delimiter.

| Field | Meaning |
| --- | --- |
| `word` | The word as written; must equal the file name. |
| `reading` | Kana reading. |
| `title` | Short English gloss. |
| `jlpt` | Optional integer 1–5 identifying the word's sourced community vocabulary level, independently of its kanji. Declare it once at the top level with an unquoted key and number. Omit when no level is established; do not use a blank, `null`, a quoted number, a duplicate declaration, or an inferred level. |
| `type` | `kango`, `wago`, `jukujikun` or `gairaigo`. Mixed on+kun words (e.g. 円高 えんだか) have no type of their own: use `kango` for an on-first compound and say in the body that it is mixed (jūbakoyomi). |
| `kanji` | Every distinct kanji occurring in the written word, including characters whose cards have not been added. Use `[]` for a kana-only spelling. Do not omit a character merely to avoid a missing-card reference. |
| `tags` | Free tags. |
| `quiz_distractors` | Optional inline list of up to 3 other exact `word` IDs that make good wrong choices for this word (plausible but clearly different, e.g. 今日 vs 今朝). Used first, before the automatic tag/kanji scoring, in both directions. Must exist, must not repeat, include the word itself, or overlap `quiz_exclusions`. Omission means automatic choices only. |
| `quiz_exclusions` | Optional inline list of other exact `word` IDs that must not appear together as quiz choices. Omission or `[]` means no curated exclusions. Use one top-level unquoted key; reject duplicate declarations, repeated/self IDs and missing targets. |
| `image`, `image_scene` | Optional legacy fallback, given together. `image` is a flat `images/<name>.webp` path (WebP, at most 100 KiB, owned by one word only); `image_scene` is its English description. This fallback is always quiz-eligible and must contain no answer-bearing text. With a scene catalog, it must match an eligible scene and its description exactly. Omit both fields for an article-only image; see the catalog contract below. |

Body: meaning and usage, how the kanji combine, synonyms and antonyms, and the distinctive nuance.
For kana-only words (`kanji: []`), the `## How the kanji combine` section is optional: omit it unless there is a spelling or
word-formation point worth making. The other three sections remain required, in order.

Vocabulary-aware app versions use an explicit word `jlpt` first. For legacy articles without this field, they retain the previous
fallback based on the hardest known written kanji; that fallback is not a vocabulary-level source. Earlier app versions ignore
word `jlpt` and always use the kanji-based calculation. N4 word study includes N5; N3 word study includes N5 and N4.
Unlike kanji cards, word articles do not require a matching JLPT tag; `tags` remain free study metadata.

The word quiz also uses `title` as the English answer label. The earlier
[candidate builder](https://github.com/stop-cran/kanji-cards-android/blob/8c9713f77083a1ff8b10b5ccb4438b51f0231fec/app/src/main/java/io/github/stopcran/kanji/core/words/Words.kt)
deduplicates exact titles and written forms, not semantic equivalents. Related tags, word type and shared kanji influence candidate
selection. Check glosses against actual meaning and register; different English wording alone does not make two synonyms valid
opposing choices. Do not distort a word's meaning merely to make its title look unique.

Exclusion-aware app versions additionally honor `quiz_exclusions`, for example `quiz_exclusions: [気分]` on 気.
That pair is excluded in both directions even if only one article declares it. Exclusions also apply between other choices
within a question, in both Japanese-to-English and English-to-Japanese quizzes. They are pairwise, not transitive:
excluding A/B and B/C does not automatically exclude A/C. The app never restores an excluded choice just to fill four slots;
a small pool can yield fewer options, as with exact-title deduplication.

Curate these pairs from actual overlapping meanings and register, not merely shared tags or similar spelling. This mechanism
does not discover every synonym or guarantee semantic uniqueness for uncurated pairs. Earlier apps ignore this field.
The validator checks declaration shape and reference integrity; editorial review establishes which pairs belong in the list.

When to add one: a pair needs an exclusion when a learner could reasonably accept either `title` as the answer for either word
(for example あげる/くれる, 開く/開ける, 良い/いい). Titles that are exactly equal need none, because the app already keeps them apart.
Homophones such as 暑い/熱い need none either: the reading quiz asks for the reading of a written word and compares readings, and
the meaning quizzes show different titles. Work through the pairs in [confusable-words.md](confusable-words.md) when you add or
reword a `title`; declare the exclusion on one of the two cards.

### Named scene catalogs

`scenes/<word>.json` is an optional schema-v1 catalog. Its `word` must match the filename and an existing word card. A nonempty
`scenes` array contains objects with these required fields:

| Field | Contract |
| --- | --- |
| `id` | Stable within the word; lowercase ASCII letter/digit groups separated by single hyphens. No duplicate IDs. |
| `sense` | Nonblank English label for the particular taught use, not a claim to cover every dictionary sense. |
| `image` | Flat `images/<name>.webp` path, at most 100 KiB. Distinct within the catalog and not owned by another word. |
| `description` | Nonblank English description suitable for accessibility and answer/article captions; no Japanese answer labels. |
| `quizEligible` | Required JSON `true` or `false`, never a quoted boolean or an omitted default. False means article-only in both picture directions. |

For example, a scene object is
`{"id":"warm-sunlight","sense":"Pleasant warmth","image":"images/example--warm-sunlight.webp","description":"A person relaxing in warm sunlight.","quizEligible":true}`.
The containing object has `schemaVersion: 1`, `word: "<exact word ID>"` and `scenes: [ ... ]`. Array order is article display order.

Catalogs are authoritative: only an **absent** catalog permits legacy synthesis (`id: "legacy"`, sense label "Illustrated usage").
A declared but missing, hash-mismatched or structurally invalid catalog disables picture eligibility for that word; it does not delete
the lexical article or fall back around an eligibility restriction. A missing or failed individual image drops that variant.
Legacy fields, when retained for older apps, must reference a catalog scene with `quizEligible: true` and an identical description.
Making that image article-only requires removing its legacy fields, not deleting its approved bytes.

Quiz scenes must be text-free and must not reveal the Japanese answer through image text, descriptions or filenames shown to the learner.
Mark explanatory diagrams, answer-bearing illustrations and scenes that cannot be fairly discriminated as `quizEligible: false`.
Eligibility and semantic distinctness require editorial/visual review; a structural validator cannot establish them.
Curated word-level `quiz_exclusions` still apply to every eligible scene. Variants do not create per-picture schedules.

The manifest lists catalogs under a separate optional `scenes` map, hashed over LF-normalized text, rather than under `files`.
Images remain under `images`, hashed byte-for-byte. Both maps contribute to `contentVersion`; omitting `scenes` retains the legacy
calculation exactly. This lets older clients ignore the new catalogs without missing-file errors. Regenerate the manifest after
catalog-only edits as well as word/image edits. Older apps understand only the optional legacy image fields, not named variants.

### Generating and reviewing scenes

`tools/onomatopoeia_scene_plan.json` inventories the uses taught by the original 200 cards and recorded later additions. It is authoring input, not a
runtime payload. Article hashes pin that basis; existing-image hashes protect approved bytes. Planned eligibility is provisional
until the generated picture is inspected. Do not infer either exhaustive coverage or owner acceptance from a generator succeeding.

Install Pillow alongside the validator's PyYAML dependency. For a scene plan:

```powershell
python -X utf8 -B tools\generate_images.py --plan tools\onomatopoeia_scene_plan.json --check
python -X utf8 -B tools\generate_images.py --plan tools\onomatopoeia_scene_plan.json --artifacts C:\path\outside-the-repo --subscription <subscription-id> --only <word>
python -X utf8 -B tools\generate_images.py --plan tools\onomatopoeia_scene_plan.json --artifacts C:\path\outside-the-repo --apply
```

The generator uses the existing deployment and shared editorial style, renews expiring authentication, and retries confirmed
rate-limit responses. Original PNGs and per-image request receipts stay in the supplied artifact directory. A completed image or
cached original is reused without another paid request. An uncertain response stops rather than blindly spending again;
`--retry-uncertain` is an explicit decision after investigating that request, not a routine retry flag. Existing outputs are never
silently overwritten. Retain rejected attempts and use a new image filename for a deliberate revision.
Run only one generator against a given artifact/output tree at a time. Provider rejection details and request IDs are retained
when supplied; a rejected request is not a completed image or a visual-review verdict.

The plan's per-scene `advisoryReview` must contain the actual output `imageSha256`, a `verdict` of `ACCEPT` or `ARTICLE_ONLY`, and
the reviewer's observations. `ARTICLE_ONLY` requires `quizEligible: false`. Keep owner decisions separately; advisory review is not
owner approval or a measured learning-effectiveness result. Inspect contact sheets, enlarging unclear images, before recording a verdict.
After inspection, make new descriptions concise accounts of what the output actually shows, not generation instructions.
Keep the original `prompt` unchanged so a clearer caption does not falsify provenance or trigger a paid regeneration.

With `--plan`, **`--apply` makes no generation requests**: it preflights all selected pictures and hash-pinned reviews, then writes
the catalogs. It does not rewrite lexical cards or add legacy fallbacks for newly illustrated words. Older clients consequently keep
their existing legacy pictures while ignoring new catalog-only media without import errors. The original `--set ... --apply`
workflow remains available for legacy single-image cards.

Wait until generation and catalog review are complete before rebuilding a publication manifest.
After applying catalogs, run `python -X utf8 -B tools\validate.py` and `python -X utf8 -B tools\build_manifest.py`; measure the final archive as well
as the image budget. Publish reproducible prompts, output hashes, actual advisory observations and owner decisions in the image
provenance record. Raw originals and authentication tokens do not belong in the content payload.

## Strokes file

```json
{ "schemaVersion": 1, "kanji": "休", "source": "KanjiVG ...", "sourceRevision": "<commit>",
  "viewBox": [0, 0, 109, 109], "strokeCount": 6,
  "strokes": [ { "id": 1, "type": "㇒", "points": [[x, y], ...] } ] }
```

Optional `orderVariants` lists extra stroke orders the app accepts as clean. Each entry must be a different permutation of the
integers `1..strokeCount`, not the default order (e.g. `[[1, 3, 2]]` for three strokes). Edit `tools/order_variants.json`
(`{ "<char>": [[...]] }`) and run `generate_strokes.py`; only add orders backed by a source (MEXT 筆順指導の手びき, KanjiVG variants).

Strokes are listed in stroke order; each stroke is 16 points sampled by arc length from the KanjiVG path.
Validation also checks file/kanji identity, schema, numeric fields and point structure. Sixteen points is the generator's convention;
the importer requires at least two finite two-coordinate points per stroke.

## Grammar exercises

For research starting points, consult the [grammar authoring source guide](grammar-authoring-sources.md).
It links inspected examples and existing batch records, with source-specific retrieval caveats; it does not replace
per-batch provenance or editorial review.

`grammar/<set-id>.json` files use `schemaVersion: 1` and contain stable construction, relationship and exercise IDs. Each exercise
has a Japanese prompt with exactly one `____` blank, an English translation, evidence from the context, an explanation,
the correct construction ID, accepted typed forms, and answer options with a rationale for every alternative. Every relationship
must have examples targeting each of its constructions. Its linked `article` must be an existing `articles/<slug>.md` file.

**Optional JLPT level:** an exercise may declare one `jlpt` integer from 1 to 5. Omit it when classification is uncertain;
explicit `null`, quoted numbers, booleans, fractions and out-of-range values are invalid. Do not add redundant level tags or
cumulative memberships. The app's new-material scope is cumulative (N3 includes N3/N4/N5), while browsing is exact; All and
Unclassified remain explicit choices. Neither filtering nor adding/changing this field resets an exercise's existing progress.

Classify the grammar required by the complete visible task, including its contrast, not merely the easier target, hardest word/kanji
or most advanced optionally accepted formulation. An N5 grammar exercise need not contain only N5 words. Preserve accepted answers,
comprehensible wording and existing translation/reading support; optional vocabulary help below is independent of grammar difficulty.
JLPT labels are sourced editorial estimates, not an official syllabus or mastery claims. Record the evidence and qualifications
in contributor source records, and leave unestablished cases unclassified. Follow the
[grammar baseline](jlpt-levels.md#grammar-baseline): Bunpro primary, JLPT Sensei secondary, with documented scope differences
and disagreements rather than vocabulary-derived or guessed levels.

**Optional introduction groups:** each group requires `id`, `label`, `facets` (`id`, `label`) and `members`
(`exerciseId`, `facetId`, `exampleKey`). IDs use `[a-z0-9-]+`; labels/reasons are nonblank. Group IDs are source-global,
but members must belong to the declaring file and have only one authored owner. Each facet targets one local construction/answer
class and has at least two distinct context keys. Near-duplicate examples share a key; a paired context may share a key across facets.
Do not merge unrelated same-spelled local constructions or change tested meaning while retaining an identity.

Optional `next` contains `{groupId, importance, reason}` recommendations (integer importance 1-3); `requires` contains group-ID
strings, not objects. Omitted arrays default empty; explicit null, duplicate/self links, unknown nested fields and malformed references
are errors. Duplicate source-global groups and missing/cyclic prerequisites reject files and their dependents. Recommendation cycles
are valid; missing optional targets warn and drop only that link. See the app's
[complete group contract](https://github.com/stop-cran/kanji-cards-android/blob/main/docs/GRAMMAR-INTRODUCTIONS.md#additive-metadata).

The app's opt-in focused-introduction pilot uses these groups without changing exercises, answers or SRS. Valid unowned exercises remain
available through labeled compatibility contrasts. Invalid annotations never silently become compatibility groups. Phase D uses the
maximum incoming importance from supported familiar groups, not summed links or exercise counts; exploration prefers score-zero
choices within its unfamiliar-first eligible pool. Recommendations cannot bypass scope/prerequisites or interrupt an active focus.
The app explains the strongest links and their source evidence locally. Group coverage/familiarity are conservative pilot
heuristics, not mastery or an official curriculum. Regenerate the manifest after adding/changing runtime metadata.

**Optional vocabulary:** an exercise may have `vocabulary` with exactly `schemaVersion: 1`, `promptSha256` and `spans`.
The hash is SHA-256 of the exact decoded prompt encoded as UTF-8, without normalization. Omission is valid legacy content;
explicit null is invalid. Each span contains `start`, `end`, `text`, `reading`, `headword`, `gloss` and optionally `word`.

- Offsets are sorted, nonoverlapping half-open **Unicode code-point** intervals in the original prompt, before replacing `____`.
  `text` must match that exact occurrence. For `𠮷野は____。`, `0..2` covers `𠮷野`; UTF-16 offsets would instead be `0..3`.
  Do not split combining sequences or overlap the blank. Repeated spellings have separate occurrences and may have different senses/readings.
- `reading` is the displayed form's pronunciation, not just its dictionary form: `建っていた` has `たっていた`, headword `建つ`.
  Supply an original, context-specific English `gloss`. Keep compounds/inflections meaningful; do not infer sense from a kanji substring.
- Optional `word` is the exact existing `words/<word>.md` identity, without a directory or extension. No slashes, control characters,
  `.` or `..`. Do not fabricate a dictionary match; omit the reference for a local gloss. Canonical references need sense/spelling review.
- At most 128 spans; nonblank text/reading/headword and word IDs are limited to 80 code points, glosses to 240.
  Integers must be JSON numbers, not strings/booleans/fractions. Unknown fields are errors.
- Annotate lexical vocabulary, not particles, grammatical auxiliaries, the blank, or the construction being tested. Never supply the
  missing answer or its explanation as a hint. A visible inflected lexical verb may be annotated unless that form is protected by the task.

## Links and safety

- Links between imported pages are relative `.md` paths (`../words/大小.md`) so they also work on GitHub. The app turns them into in-app navigation with a back button.
  Relative links in imported content must target `kanji/`, `words/`, or `articles/`: `docs/` is not included in the content manifest.
- Other links must be `https://`. Raw HTML is not allowed. Text that names a kanji or word without a card is left as plain text.
- A word article must link (e.g. `[冗](../kanji/冗.md)`) every kanji listed in its `kanji:` field that has a card in `kanji/`; kanji without a card are exempt. `tools/validate.py` enforces this.
- Review state in the app is keyed by the kanji character, so don't rename cards; change `title` and body freely.
